## 踩到的坑(记录备查)
- **端口冲突**:旧工具 `实时朗读器.exe` 占了 8790,Python 默认 `allow_reuse_address=1` 会让两个进程都"绑上"同一端口,请求被旧进程接走 → "HTTP 200 但正文 0 字节"。新版用 **8890** 并关掉复用 ✓
- **`.ps1` 必须带 UTF-8 BOM** ✗:PowerShell 5.1 把无 BOM 的 UTF-8 当 GBK 读 → 中文乱码 → 语法错误(`rename.py` 重写时抹掉了 BOM)
- **`player.cpp` 需要 `installer\compat\EventToken.h`** ✗:旧项目的 `compat/` 没一起搬过来
- **构建用 Python 要有 Pillow** ✗:`build.ps1` 优先找 `.venv\Scripts\python.exe`,新项目没 venv → 回落到系统 Python → 生成图标失败(用 `-Python` 指定即可)
- **`GetCurrentProcess()` 读内存返回 0** ✗:没声明 `restype=HANDLE`,64 位伪句柄被截断 → 必须写全 `argtypes/restype`

## 实战案例:AnaDos(`D:\Program Files\AnaDos`,Unity 6000.3.6f1 / IL2CPP x64 / UTAGE ADV)

这是一次完整的"装完游戏闪退"排查,结论写下来备查。

### 现象
1. 装完挂钩后游戏**联网报错**("網路處於不穩或無法連線")。
2. 换 `version.dll` 后联网正常,但**游戏在载入→标题的切场景处闪退**,稳定复现(第 80~110 秒)。

### 定位(A/B 对照,每次启动盯 150 秒)
| 组 | 配置 | 结果 |
|---|---|---|
| 1 | BepInEx + 插件(去掉 XUnity) | 崩溃 @90s |
| 2 | 只留 BepInEx 核心 | 存活 |
| 3 | 无 BepInEx 纯净原版 | 存活 |
| 4 | 插件档位 `gameonly`(只挂游戏自己的入口) | 存活 ✓ |
| 5 | 插件档位 `tmpro`(额外挂 `TMPro.TMP_Text.set_text`) | 崩溃 @80s |
| 6 | 插件档位 `tmpro_setonly`(挂 TMPro `SetText`,排除 `set_text`) | 存活 ✓ 22 个方法 |

崩溃点三次完全一致:`coreclr.dll +0x1d1fdd`,`0xc0000005`。

### 两个根因
1. **注入代理**:Doorstop 的 `winhttp.dll` 顶替了游戏的联网模块 → 换 `version.dll`/`winmm.dll` 即可(同一份 DLL 换名字)。
   → `HookManager` 支持 `proxy` 参数 + 每游戏记事(`_聆阅_注入代理.json`),UI 在「设置 → 读取模块」。
2. **挂钩目标**:
   - `UnityEngine.UI.Text.set_text` 是引擎高频方法(载入进度条每 0.05 秒一次),切场景时会在**已销毁**的对象上再调一次 → 原生异常穿过 托管↔原生 跳板 → Il2CppInterop 刷 `native->managed trampoline` → `coreclr.dll` 访问冲突闪退。
   - `TMPro.TMP_Text.set_text` 同理(引擎自己在布局/销毁时会调)。
   - 关键词:**属性 setter(`set_text`)不能挂**,要挂就挂游戏自己的高层入口(`LocalizeTextMeshPro*` / `Utage.AdvCommand*` / `LocalizeData`)。
   → 插件 v3 加了档位文件 `<游戏>\BepInEx\storyhook_mode.txt`(`profile=` / `args=`),默认 `tmpro_setonly`。

### 顺带修掉的
- **XUnity 全部移除**(Mono/IL2CPP 载荷 + 安装时清理):它自己也会钩 `set_text`,而且把中文游戏往英文翻(`FromLanguage=ja → Language=en`)。
- **`if (c > 2000) return;` 是隐形杀手**:所有台词都走同一个方法,挂上 2000 次之后插件永久闭嘴 → 游戏读一会儿就没字了。IL2CPP 版同样撤掉了这个上限。
- **自己编插件**:机器只有 .NET 运行时没有 SDK → `hooks\il2cpp_src\build_plugin.ps1` 用系统自带 `csc` 直接对着游戏 `dotnet\` 里的 .NET 6 程序集编(net6 目标),不再依赖 SDK。

### 产品化
- 装机端会在**游戏进程异常早退**(<240 秒且已抓到过文本)时提示:「像是闪退 → 换注入方式为 version.dll / 换挂钩档位」。

## 功能:自动下一句(剧情朗读完自动点)

**要求**:剧情**朗读完**之后停一下(默认 1 秒),自动帮玩家点一下游戏画面进下一句;设置里有开关。

**实现**
- `core/autoclick.py`(新,自带窗口查找,不依赖旧项目 `gamewin.py`):
  - `find_game_window(exe)`:`tasklist` 拿 PID → `EnumWindows` 取该进程可见、未最小化、面积最大的窗口
  - 安全把关:目标点上的窗口必须是**这个游戏进程**(`WindowFromPoint` + `GetAncestor(GA_ROOT)`),
    否则一律不点 —— 玩家切出去看网页时绝不会被误点
  - 点哪儿可选:`center` 窗口中央 / `low` 下方文字框(0.78h)/ `bottom` 底部(0.92h)
- `webapp/server.py`:`Speaker.say(text, interrupt, story=False)` 增加 `story` 标记;
  朗读线程里 `tts.speak()` **返回即代表这段播完**(三条语音路径都是同步语义),随后调
  `_auto_next_after_read(gen)`:按设置分段等待 delay,期间 `gen` 变了(玩家按停止/新剧情打断)
  或 DLP 关了/游戏没跑 → 立刻放弃。
- 配置:`auto_next` / `auto_next_delay` / `auto_next_point`;界面在「设置 → 自动下一句」。

**两个坑(实测)**
1. **归一化绝对坐标不准**:`SendInput` 用 `MOUSEEVENTF_ABSOLUTE` + `65535` 归一化,
   目标 (600,500) 实际点到 (611,447)。改成 **`SetCursorPos` 定位 + 只注入按键**后偏差为 **0**。
2. `WindowFromPoint` 拿到的可能是子窗口,必须 `GetAncestor(GA_ROOT)`;最小化窗口坐标是
   `(-32000,-32000)` 要跳过。

**自检结果**:喂剧情 → 念完 → 停 1 秒 → 点中窗口正中(偏差 0);念到一半按停止 → 不点;
目标点被别的窗口盖住 → 拒绝并写日志说明原因。

### 补充:没有文字的过场剧情(2026-09 加)
Utage 有些步骤**一个字都不设置**(画面上只有"点击继续"的指示/演出效果),抓不到台词就不会点,
自动朗读卡住。修法:后台线程每 0.5 秒看一眼,「多久没有新台词」超过 `auto_next_blank_wait`
(默认 2.5 秒)就再点一次。三道闸:
- 必须 `auto_next` + `auto_say` + `auto_next_blank` 都开着,并且之前确实读到过剧情(说明在剧情里)
- 正在朗读(`tts.is_playing()`)或队列里还有没念的 → 不点
- 连续空点超过 `auto_next_blank_max`(默认 6)次 → 停手并提示"可能停在选项/菜单上"
- 拿到新台词就把计数清零
- 循环里**不能**调 `_proc_running()`(它每次都起一个 tasklist 进程),改用 `RUNNING["active"]`

自检:喂一句 → 正常点 1 次 + 空点 3 次(测试把上限设成 3)→ 到上限停手 → 新台词到达后计数归零 ✓

### 第二版:排版重做 + 修"卡住"(用户反馈)
用户反馈:①显示的信息不够(要有**读取文字中 / 朗读中**、状态、**内存**、**读写速度**);
②**悬浮窗有时会卡住**,只能"关掉再打开"。

**排版(现在)**
- 未展开 246×58:状态点 + 大字状态(读取文字中 / 朗读中 / 待机中 / 游戏未运行…),
  第二行 `内存 186MB · 读取 12.4字/秒 · 已读 128`,右边 ▾
- 展开 392×286:状态 + 收起 / 游戏 / 当前台词(2 行) / **2×2 指标格**

(要碰 WinRT 媒体接口)→ 一旦它阻塞,整个悬浮窗就不再重画,表现就是"卡住"。
**修法(三层)**
1. **独立采样线程**每 0.5 秒把要显示的数据算好放进 `_FLOAT_DATA`,窗口线程**只读缓存**;

2. `start()` 必须**换一个新的 `threading.Event`**,否则老 Event 还留着 set 状态,
   第二次启动会"假成功"(这是"关掉再打开有时起不来"的原因)。
3. **看门狗**每 5 秒检查:`alive=False`(线程死了)或 `last_paint_at` 超过 12 秒没推进(绘制停摆)

   并写日志「悬浮窗好像卡住了,正在自动重建 / 已自动恢复」。**玩家不用再手动关掉再打开。**

自检:未展开 246×58 / 展开 392×286 / 不抢焦点 ✓;内存、朗读速度(5.0 字/秒)读数正常 ✓;

## 严重 bug 复盘:自动点击抢在朗读前面(用户实测)

**现象**:开了「自动下一句」后,朗读还没念完就点下一句了。

**根因**:「没有文字的过场」那段判断"是否正在朗读"用的是 `tts.is_playing()`,
而它读的是 **WinRT 媒体播放器状态**,有两个致命的空档:
1. **离线神经网络语音**(`sherpa:*`,用户用的 `fanchen_C`)每次都先**合成 1~3 秒**再播放;
   合成期间根本没有播放器 → `is_playing()` 返回 False。
2. 本机语音走 `pyttsx3` 回退等路径时 `_current_player` 也可能是 None。

而 `auto_next_blank_wait` 默认 2.5 秒 → 合成的 2~3 秒正好被当成"这一步没有文字"→ **抢在开口前点**。

**修法(两层)**
1. 改用朗读线程自己维护的 `_SPK["on"]` 标志 —— 它在 `tts.speak()` **整个调用**期间为真,
   涵盖 合成 / 变调 / 播放 / 回退,三条语音路径都准。**判断朗读绝不看 `is_playing()`**。
2. 等待时间从 **`_SPK["end_at"]`(念完的时刻)** 起算,不再从"抓到文字"起算:
   `base = max(last_line_at, last_click_at, end_at)`。

**回归测试**(把 `tts.speak` 换成"睡 4 秒"模拟长台词,且 `is_playing()` 全程 False):

## 装机后「Windows 本机语音」全空 —— 内嵌运行时少了一个 WinRT 包

**用户反馈**:界面上说"这台电脑上没有检测到 Windows 本机语音",但系统里明明有。

**定位**(拿两个解释器对照跑,一次就分出来了):
```
装机内嵌 Python 3.13.15 (D:\聆阅\runtime\python):
    from winrt.windows.media.speechsynthesis import SpeechSynthesizer
    → ModuleNotFoundError: No module named 'winrt.windows.foundation.collections'
开发 venv Python 3.13.13:
    → SpeechSynthesizer.all_voices = 3 个(Microsoft Huihui / Yaoyao / Kangkang)
```

**根因**:`requirements.txt` 只列了 `winrt-Windows.Media.*` / `Storage.Streams` / `Foundation`,
**漏了 `winrt-Windows.Foundation.Collections`**。`all_voices` 返回的是 `IVectorView`,
少了这个投影包会直接抛 `ModuleNotFoundError`,而 `tts.list_voices()` 里是 `except: pass`
→ 界面拿到空列表 → 显示"没有检测到本机语音"。**连选它出声也会失败**(`_get_synth()` 同样要它)。

**修法**
1. `requirements.txt` 补上 `winrt-Windows.Foundation.Collections>=2.0`(并写了注释说明为什么不能少)
2. 给**已装的运行时**直接补装一份,用户不用重装程序就恢复:
   `D:\聆阅\runtime\python\python.exe -m pip install winrt-Windows.Foundation.Collections`
3. 重打安装程序(requirements 变了,`build_runtime.ps1` 会重建内嵌运行时)

**验证**
- 装机运行时:枚举到 3 个 + **真的出声**(`tts.speak('本机语音已经可以用了。')` 2.8 秒念完)
- 新构建的便携运行时:同样枚举到 3 个 ✓(即**以后新装的机器不会再踩**)
- 代码里用到的 6 个 winrt 模块逐个 import:全部 OK
- 与 venv 对照:装机仅少 `globalization / graphics_imaging / media_ocr` —— 那是旧 OCR 项目的,聆阅不需要

**教训**:这类"少一个投影包 → 异常被 except 吞掉 → 界面静默变空"的问题最难查;
凡是"列表为空/功能不生效"的 except 分支,都应该留一条日志,而不是 `pass`。

## 「回存档重读上一段剧情读不出来,只能重启程序」

**用户反馈**:第一章读完后进了下一段剧情,读档回去想再听一遍上一段 → 读不出来,重启程序才恢复。

**复现**(直接喂过滤器,第二遍同一段):
```
第一遍 读到 3 句  ✓
第二遍 读到 0 句  ✗   ← 复现
recent 里记着:三句都在,时间 1.6 秒前 / last_committed = 最后那句
```

**根因**:`StoryFilter` 的去重记忆
- `last_committed`:和上一句完全相同 → 丢
- `recent`:120 秒内见过的句子,其中**45 秒内一模一样**的直接丢(防界面刷屏/打字机残留)

读档重读时读的正是**刚刚才读过的句子** → 全被当成重复吞掉;重启程序记忆清空 → 又正常。
这也解释了"为什么非重启不可":去重窗口 45 秒,玩家一般是立刻读档,自然每次都撞上。

**修法**(区分"重读一整段"和"界面刷屏")
- 重读的特征:一句接一句、**彼此各不相同**、但都见过(A→B→C)
- 刷屏的特征:同一句反复出现(A→A→A)
- 新增 `_dup_kind()`(把原来散在 `commit()` 里的四类判定抽出来)和 `_looks_like_replay()`:
  连续 **2 句各不相同的旧句子** → 判定为读档重读 → `forget_recent()` 清空记忆并放行,
  同时回调 `on_replay` 让界面提示"已放开去重"
- 误判也没关系:放行之后还有 `is_story_text` 严格模式把关,界面说明照样滤掉
- 另加手动保险:实时剧情页工具条上「**允许重读**」按钮 → `/api/story/allow-replay` → `forget_recent()`

**实测四场景**
```
① 读档重读同一段  第一遍 3 句 / 第二遍 2 句 / 第三遍 2 句   ✓ 能重读了
② 同一句刷 8 次   读出 0 次                                ✓ 仍然压得住
③ 打字机残句      没漏出来                                  ✓
④ 点「允许重读」  立刻放行 3 句                             ✓
```
(第二遍会少第一句 —— 它正是触发判定的那一步;同一会话里再读一次就完整了。)

### 补充:默认配音 + 修"名字被上一句污染"(2026-09)

**① 默认配音**(`cast_default`,默认 `sapi:Microsoft Huihui`)
- 覆盖两种"没有专属配音"的情况:① **没有角色名的台词**(旁白)② **还没单独配音的新角色**

- 界面:角色配音页顶部一行「默认配音」+ 语音下拉 + 试听(带主色边框)
- 接口:`/api/cast/default`

**② 名字识别修复(重要)**
现象:第一句有名字、第二句游戏里**明明没有名字**,却仍被套上第一句的角色名(连配音也一起错)。
根因是**两层都把"空名字"过滤掉了**,导致"名字框被清空"这个信号永远传不到读取端:
```
插件 hooks/mono/StoryHook.cs   if (string.IsNullOrEmpty(s)) continue;   ← 空名字不上报
过滤器 core/storyhook.py       if not text or len(text) < 2: return     ← 空文本提前返回
```

**修法**
1. 两个插件(Mono + IL2CPP)都加 `IsNameMethod()`:凡是 `NameText / CharacterLabel / NameLabel`
   这类方法,**空值也照报**(写成空文本),并把这些方法名加进 IL2CPP 的挂钩名单
2. 过滤器把"名字方法"的判断**提到空文本检查之前**:空/超长/含假名 → `speaker = ""`(这一句没发言人),
   并记 `speaker_t`
3. `commit()` 里那个"猜出来的名字候选"不再覆盖游戏刚给过的名字:
   `fresh = speaker_t 在 8 秒内` → 游戏说了算(含"清空"),不猜

```

③ 名字框被清空     → ④ 旁白 = 街上一個人也沒有。      ✓ 不再被污染
```

## 日志加强 + 存档界面不读也不点(用户反馈)

## 修:卸载残留 + DLP 开关重新定位(用户反馈)

### ① 卸载会留下 `.bak_聆阅` 和 `_聆阅_注入代理.json`

1. `install()` 里备份只在"`.bak_聆阅` 还不存在"时才写进清单 → 如果上一次装留下的 bak 还在,

- `install()`:只要 bak 存在就记进 `manifest["backup"]`,不管是不是这次新建的
- `uninstall()`:还原备份之后,**兜底清扫** `*.bak_聆阅` + 注入代理记事本 + 清单本身;

- 复查逻辑修正:从备份**还原回来的游戏原文件**当然还在,不能算残留
  (以前会把它们误报成"卸载不完整")

**实测**(连装/卸 3 轮)
```

游戏原本没有       → 卸载后一个不剩 ✓ ok=True
```

- 语音朗读页 `renderVoices()` 也加了同样的签名保护(以前每 0.4 秒重建 14 行,点起来会闪)

**实测**(无头浏览器自动化)

```
2.5 秒后(≈6 个刷新周期):
   同一个 DOM 节点吗?  是 ✓ (没被重建)
   焦点还在下拉框上吗?  是 ✓
   选的值得以保留吗?    是 ✓ (chaowen_hq)
```

## 6) 静默推进:自动点击不再动鼠标

先做了反编译侦察(`docs\_probe\UTAGE-advance-report.md`),结论推翻了原来的设想:

> UTAGE 的**左键推进不走 `UnityEngine.Input`**,走 UI EventSystem
> (`AdvUguiManager.OnPointerDown → OnInput`);老式 `Input` 只管右键/滚轮/Ctrl/回车。

所以"伪造鼠标按键"对推进剧情**无效**(IL2CPP 上还属于已知崩溃类)。
真正的入口是引擎自己给回车/滚轮用的那套:

```csharp
engine.Page.InputSendMessage();      // 等价于"玩家点了一下"
engine.UiManager.IsInputTrig = true; // 满足 AdvCommandWaitInput/WaitCustom/Movie
```

两个要点:① `IsInputTrig` 每帧在 `AdvUiManager.LateUpdate` 里被清零,所以**必须在 Update 阶段设**;
② 两者都是**一帧脉冲**,一次调用只推进一步,不会变成每帧狂点一路跳过;
③ `AdvSelectionManager.IsWaitInput` 为真(选项菜单)**绝不点击**,否则会替你选一个。

两个插件都实现了(用反射找类型,不引用游戏装配件,换游戏不用重编):
- Mono:`StoryHook.dll` 在插件自己的 `Update()` 里轮询请求文件;
- IL2CPP:`StoryHookIl2Cpp.dll` 挂 `Utage.AdvUguiManager.Update` 的 **Postfix**
  (目标是 UTAGE 自己的方法,避开会让 AnaDos 闪退的 TMPro / 引擎模块)。
- 通道:`<游戏>\BepInEx\_聆阅_点击请求.txt`(App 写)→ 插件读走并删掉 → 回写
  `_聆阅_点击回执.txt`(ok/fail + 原因)。App 侧 `do_advance()` 先静默、失败再退回老办法。
- 设置页有「静默推进」「失败时用鼠标兜底」两个开关,还有一个**「测试一次静默推进」**按钮,
  游戏停在对话上时点一下就知道插件点不点得动。

## 7) 文本翻译:实时把游戏改成简体中文

照「游戏一键汉化工具」的思路(注入 XUnity.AutoTranslator + 自定义翻译后端),但后端换成本机 AI:

```
游戏 set_text(日文) → XUnity 拦下 → GET /api/translate?from=auto&to=zh-CN&text=…
   → 本机 AI 翻译(带落盘缓存)→ 返回**纯文本译文** → XUnity 写回游戏文本框
```

- payload 放在 `payload\translate\{mono_x64,il2cpp_x64}\`(XUnity.AutoTranslator 5.6.2,MIT,共 1.6MB),

  **响应体必须是纯文本译文本身**,返回 JSON 的话游戏里会显示成一串 JSON;
  出错也必须 200 + 原文,否则插件连续失败 5 次会自己关掉。
- `core/translate.py`:落盘缓存、简体校验(模型偶尔回繁体/日文 → 用 `is_bad_output` 拦下并给原文,
  另配一张常见繁体→简体兜底表)、`prefetch()` 预热。
- 「译文也走朗读」是**玩家自己选**的开关:开了就把 XUnity 回写的中文顶掉原文再朗读
  (`filter.replace_pending()`,打字机定稿时间自动 +1 秒等译文);关了只改画面,朗读仍按原文。
- 关掉翻译 = 只删我们清单里记过的文件,不碰玩家自己装的东西;
  **翻译开着时「安装 LDC」不会再顺手清理 XUnity**(以前那段逻辑会把翻译插件删掉)。

## 9) 男声包:实测结论与目录更新(第二批)
